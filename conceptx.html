Overview

ConceptX started as a Learning Management System (courses, content, exams) and grew into a full School Management System. I joined in January 2023 and worked on the original Laravel 8 LMS. Since mid-2024 I've worked on its successor, an API-only Laravel 11 backend with versioned REST endpoints under /api/v1.

Most of my work is on the backend: turning school requirements into database structures, APIs and permission rules that the web app, the mobile app and the admin panel all share.

Engineering Decisions

Real problems from my work on the platform, described in general terms.

1 · Permissions for a school with many kinds of users

Problem
One school has administrators, staff in different positions and departments, instructors, students and guardians. They all touch the same classrooms, attendance, assignments and grades, but each needs different access.
Approach
Store school-level roles and permission modules as data, and enforce them through one Laravel Policy per resource instead of scattering checks across controllers.
Challenge
Some access comes from a relationship, not a role. A guardian should see their own child's classes without holding a staff permission.
Solution
Policies combine role permissions with membership checks, so membership grants view access where it should. I've built and maintained policies for attendance, classrooms, assignments and answers, forms, evaluation weights and lectures, and added permission logging to make access issues easier to trace.
Result
Each resource has its access rules in one place, and the same rules apply to the web app, the mobile app and the admin panel.

2 · Speeding up heavy list endpoints

Problem
Frequently used list endpoints (schools, users, profiles, form submissions) ran nested relationship queries and returned more related data than the screens needed.
Investigation
Reviewed the queries each endpoint generated and compared the API Resource output with what the web and mobile screens actually used.
Solution
Replaced nested whereHas chains with whereIn subqueries, limited eager loading to the relations and columns needed, used withCount instead of loading whole collections, and removed unneeded fields from the API Resources.
Result
Less database work per request and smaller responses on some of the platform's most-used screens.

3 · Shipping safely to a live system

Problem
Schools use the platform daily. A broken migration or a regression affects real students and staff straight away.
Approach
Test at several levels before release, and make deployment a repeatable pipeline rather than a manual process.
Implementation
I test features at unit, feature, integration, end-to-end and regression level. The CI pipeline runs the test suite against MySQL, backs up the database, runs migrations, rebuilds caches and restarts the queue and WebSocket workers.
Result
Every change reaches production through the same tested path, with a backup taken before the schema changes.
